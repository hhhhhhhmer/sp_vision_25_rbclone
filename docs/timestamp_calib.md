# 图像—姿态时间失配 τ 的自标定

## 1. 它是什么

视觉的整个跟踪状态都建立在「世界系」上，而世界系是由云台姿态四元数定义的：

```
p_w = R(q(t)) · p_g          // solver.cpp: xyz_in_world = R_gimbal2world * xyz_in_gimbal
```

`q(t)` 里的 `t` 是图像时间戳。但这个时间戳是**驱动收到整帧的时刻**，不是光子打进传感器的时刻；
云台四元数的时间戳同样是「串口收到帧的时刻」。两者之间的固定差就是 τ：

```
真实曝光时刻 ≈ t - τ            τ = 曝光中点 + 读出 + 传输 + 串口 + 调度
```

用错 τ 的后果不是「提前量短了」，而是**整个目标在世界系里绕云台转了一个角度**：

```
角度误差 = ω · τ                // ω = 云台角速度
横向误差 = 距离 × ω · τ         // 5 m 处 1 ms × 1 rad/s ≈ 5 mm
```

因为下发角也在同一个被转过的世界系里算出来，闭环不会自我纠正，火控门限（`|gimbal_yaw - cmd| < 2°`）
也看不见它 —— 它就是稳定的系统偏差，扫动方向反过来，偏差方向也跟着翻。

## 2. 为什么可以自标定

关键事实：**装甲板在云台系下的位置 `p_g` 与姿态无关**（`Solver::try_solve` 里由 PnP + 手眼外参直接给出），
姿态只参与「把 `p_g` 旋到世界系」这一步。

所以对一个**静止目标**有：

```
p_w,i(τ) = R(q(t_i - τ)) · p_g,i        应当对 i 保持不变
```

τ 取错时，`p_w,i` 会随着云台转动在一段圆弧上滑动；τ 取对时它缩成一个点。
于是标定就退化成一维搜索：

```
τ̂ = argmin_τ  Σ_i | p_w,i(τ) - mean_j p_w,j(τ) |²
```

这个 τ̂ 一次性涵盖曝光、读出、USB/网口传输、串口、线程调度在内的**全部固定延迟**，
不需要知道曝光时间，也不需要秒表。灵敏度正比于 `距离 × 角速度`，所以采样时必须让云台摆起来
（云台不动时所有 τ 给出同样的结果，代价函数是平的，程序会直接判「激励不足」）。

不确定度按 `σ_τ = sqrt(σ_p² / Σ|ω_i × p_i|²)` 估计，典型的 3 s 摆动 + 3 m 目标 + 1.5 cm 观测噪声可以到 **0.1~0.3 ms**。

## 3. 怎么用

### 方式 A：自动摆动（推荐，不需要人会摆）

```bash
./build/timestamp_calib_test ../configs/rb_auto_aim.yaml --auto
```

1. 把装甲板固定在静止位置，让它在画面里（差几度没关系，程序自己对准）
2. 把遥控**切到自瞄模式**——下位机只在自瞄模式下执行视觉角度；程序本身不发自瞄帧之外的东西
3. 按 **空格**：程序接管云台 → 0.5 s 平滑对准到装甲板 → 绕该方位 ±20° / 1.2 Hz 摆 3 s → 自动拟合

参数可调：`--amplitude 25 --freq 1.5 -d 4`（摆幅 5~40°，频率 0.3~3 Hz，时长 1~10 s）。

安全约束（都在代码里写死）：
- 摆动中心偏离按下空格时的角度**不超过 45°**，摆幅不超过 40°
- 采样期间**任意键立刻中止**并连发 3 帧 `mode=0` 把云台交回遥控
- 目标丢失超过 0.6 s 自动中止；控制器超时 3 s 强制释放；析构时一定会释放
- 程序不发开火指令（`fire=false`）

> 自动模式的前提是**下位机确实执行视觉角度**。如果云台没动，程序会判「激励不足」并提示
> 检查遥控模式/电控。第一次用建议先手动确认云台响应正常，再跑自动。

### 方式 B：手动摆动（不接管云台）

```bash
./build/timestamp_calib_test ../configs/rb_auto_aim.yaml
```

1. 把装甲板固定在静止位置（靶车架起来/靠墙都行），保证它在画面里
2. 让云台保持在**遥控/空闲模式**（本程序不发控制帧）
3. 按 **空格** 开始采样（默认 3 s，可用 `-d 5.0` 改长）
4. 采样期间用遥控让云台**左右快速摆**：幅度 ±20°~30°、1 Hz 左右，目标本身千万别动
5. 采样结束自动拟合，终端打印结果

```
================ 时间戳标定结果 ================
采样: 214 帧，剔除 8，参与拟合 206
云台激励: RMS |w| = 6.31 rad/s，峰值 9.14 rad/s（采样 3.0 s）
tau = +7.31 ms  +- 0.19 ms
世界系离散度: 21.4 cm (tau=0)  ->  1.8 cm (tau=tau)
前后半段一致性: +7.44 / +7.19 ms（差 0.25 ms）
建议: configs/rb_auto_aim.yaml 里写 timestamp_offset_us: 7310
      姿态查询改成 gimbal.q(t - <timestamp_offset>)
```

**怎么判断结果可信**：`ok=1`（不是「不可信」）、`σ` 小于 0.5 ms、前后半段差小于 ~1 ms、
离散度显著下降。任何一条不满足，程序都会打印原因并提示重来。

## 4. 怎么落地

```yaml
# configs/xxx.yaml
timestamp_offset_us: 7310   # 来自 timestamp_calib_test
```

```cpp
// 姿态查询统一用上这个偏移（现在是散落在各程序里的 t-3ms / t-3800us / t）
auto q = gimbal.q(t - camera.timestamp_offset);
```

注意：`timestamp_offset_us` 目前**只是被 `Camera` 读进来存着**，没有任何程序用它
（见 [io/camera/README.md](../io/camera/README.md)）。所以标定之后必须自己在程序里减掉，
或者按 `timestamp_offset_us` 统一改一处。

## 5. 几个边界

| 情况 | 结论 |
|---|---|
| 换曝光时间 | τ 里的「曝光中点」那一项会变（`exposure_us/2`），换曝光超过 1~2 ms 建议重标 |
| 换相机/换串口线/换主机 | 必须重标（传输延迟完全不同） |
| 目标必须静止 | 采样期间目标动了，前后半段会明显不一致，程序会拒绝出结果 |
| 云台必须摆动 | RMS 角速度 < 0.5 rad/s 直接判「激励不足」 |
| 自动模式云台不动 | 遥控没切自瞄模式 / 电控没使能视觉角度 / 下位机用的是另一种帧（试 `--sb`） |
| τ 超过 ±20 ms | 顶到搜索边界会报错；先检查是不是配错了相机/云台 |
| 标定后仍想验证 | 打 5 m 静靶，云台左扫一遍右扫一遍：弹着点随方向**翻边**说明 τ 还没对齐，永远偏同一侧则是标定/`yaw_offset` 问题 |

### 顺带修掉的问题

`Gimbal::q(t)` 原来是从一个消费式队列里 `pop` 出样本，因此：同一时刻不能被查询两次、不能回看过去、
队列满时会丢新样本、串口反馈掉队时会**无限阻塞**视觉线程。改成保留 15 s 的只读历史缓冲后，
这些问题都不存在了，标定也才能按不同 τ 重放同一批图像。
